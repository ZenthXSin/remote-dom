# 页面更新延迟优化

WebSocket 客户端通过 `render-flow` 的 `window: 3` 启用最多三帧在途更新。旧客户端不传窗口大小时仍使用一帧，服务端限制窗口为 1–3。渲染确认可以累计确认连续帧，错误 epoch 或未发送的序号不能释放窗口；输入确认不占用渲染窗口。

每个连接仅持有一份共享的不可变快照作为差分基准。窗口满后合并到最新状态，确认释放窗口时发送差分，不因短期历史淘汰而反复发送整个页面。重连和重新同步仍从完整快照开始。

封闭 Shadow DOM 的整树发现改为最多每 750 ms 一次，新文档立即发现。已发现组件中的变化继续实时采集；活动检查和页面采集合并成一次 CDP 调用。这不改变目标网页脚本，也不跳过正常页面内容采集。

对照测试人为延迟第一帧确认 350 ms：更新送达由旧实现的约 354 ms 降至优化后的约 40–57 ms。这是本地受控测试，不是用户到任意网站的端到端延迟承诺。另验证窗口上限、错误确认、积压合并、重新同步、输入、断线恢复及动态封闭组件。
