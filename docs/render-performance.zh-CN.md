# 页面更新延迟优化

WebSocket 客户端通过 `render-flow` 的 `window: 3` 启用最多三帧在途更新。旧客户端不传窗口大小时仍使用一帧，服务端限制窗口为 1–3。渲染确认可以累计确认连续帧，错误 epoch 或未发送的序号不能释放窗口；输入确认不占用渲染窗口。

每个连接仅持有一份共享的不可变快照作为差分基准。窗口满后合并到最新状态，确认释放窗口时发送差分，不因短期历史淘汰而反复发送整个页面。重连和重新同步仍从完整快照开始。

封闭 Shadow DOM 的整树发现改为最多每 750 ms 一次，新文档立即发现。已发现组件中的变化继续实时采集；活动检查和页面采集合并成一次 CDP 调用。这不改变目标网页脚本，也不跳过正常页面内容采集。

对照测试人为延迟第一帧确认 350 ms：更新送达由旧实现的约 354 ms 降至优化后的约 40–57 ms。这是本地受控测试，不是用户到任意网站的端到端延迟承诺。另验证窗口上限、错误确认、积压合并、重新同步、输入、断线恢复及动态封闭组件。

## 独立同步线程与输入

支持 Web Worker 的浏览器将单条 WSS 的收发、JSON 解析及连续页面更新合并放到专用 Worker 中。Worker 最多向界面交付一份等待渲染的更新，其余在三帧网络窗口内合并；操作确认和控制消息直接交付。页面 DOM 操作仍在主线程。Worker 脚本仅从同源加载，并且只连接同源会话流；CSP 不开放第三方脚本。

Worker 无法创建或加载失败时回退原生 WebSocket。连接中断后不重放未确认输入，原有 HTTP 备用链路仍可使用。连续输入改为 16 ms 节流，避免不断重置等待时间导致只有停顿后才同步；中文组合输入在确认时提交。渲染切片之间优先接收确认元数据，DOM 对账继续按顺序执行以保护光标和较新的本地输入。

测试包括：主线程人为阻塞 650 ms 时 Worker 仍解析收到的消息；等待渲染时输入确认仍可送达；更新合并；创建和加载失败回退；连续输入及中文组合输入；真实 TLS/WSS、断线恢复、触摸和布局回归。

## 样式复用与慢确认输入合并

元素样式、资源版本和根节点滚动处理方式均未变化时，复用已应用的样式，避免属性、选择或滚动状态更新重复读取和设置全部 CSS。缓存绑定实际元素，元素替换自动失效；资源到达、样式变化、默认值恢复仍重新应用。

1200 节点的属性更新测试中，重复样式读取由 100800 次降为 0，更新耗时从约 419 ms 降至 104–137 ms。数字来自受控浏览器测试，不代表任意网站的端到端响应时间。

连续打字在前一输入确认前合并本地新文字，收到确认后提交最新值；点击、键盘命令、组合输入确认和表单控件变化会先刷新待提交文字以保持顺序。延迟输入确认 220 ms 的回归验证不会逐条积压旧文字，最后内容与远端一致。
