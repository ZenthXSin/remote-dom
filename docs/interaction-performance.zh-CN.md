# 本地交互调度

镜像页面保留本地输入和滚动；需要远端脚本处理的操作仍取决于网络、目标网页和采集耗时。本地渲染基准不能当成端到端点击延迟。

拖动时只保留一个尚未确认的移动事件和最新的真实坐标。收到确认后立即发送最新位置；松开时先发送最后的位置，再发送松开事件，不等待旧移动的确认。不合并按下、松开、取消或点击，也不生成插值轨迹。断线重置和取消会清理待发坐标。

样式更新先比较协议里的属性值，仅对变化的属性调用 CSSOM。移除属性时恢复默认值；资源到达时重新解析相关 URL；根滚动模式变化时更新 overflow。`gap` 简写改变后仍重放行列间距，避免简写覆盖未变化的长属性。

渲染各阶段按约 8 毫秒的 JavaScript 工作片段让出执行机会。支持的浏览器使用 `scheduler.yield()`，其他浏览器继续使用定时器。每次恢复渲染前重新检查正在编辑的区域，保护在渲染中途开始的输入和中文组合输入。浏览器自身的布局与绘制仍可能超过这个片段预算，8 毫秒不是整体帧耗时保证。

回归测试：

- `pointer-backpressure.test.ts`：延迟确认时合并真实坐标，最终位置和松开顺序正确。
- `style-delta.test.ts`：1200 个节点各变一个属性，只访问相关 CSS，校验默认值和简写恢复。
- `render-editing.test.ts`：批量更新中途开始中文输入，剩余渲染不会覆盖文本。
- 继续验证拖动、双击、触摸、HTTP/WSS 输入、滚动、资源到达和布局恢复。

## 按查看和渲染进度采集

后台采集现在优先让出执行机会给排队中的输入。没有 WSS 查看者且两秒内没有查看请求时，暂停周期性整页采集；所有 WSS 查看者的渲染窗口都已满时，也暂停周期采集。首次快照和输入后的强制同步不受这些条件影响。渲染确认恢复后继续同步最新状态，HTTP 查看请求单独记录，避免被另一条停滞的 WSS 连接阻塞。原有最多三帧的有序传输流水线继续保留。

这减少无人查看或客户端落后时的无效浏览器采集，并不代表单次整页采集或网络往返耗时已经降低。增加相同状态的并行 WSS 推送不能消除这些成本。回归测试覆盖无查看者暂停、恢复后的最新状态、强制反馈、输入优先、旧版 WSS 客户端及 HTTP/WSS 混合查看。


## 降低安静页面的检查开销

DOM 变更、输入、滚动、焦点、加载、动画和媒体事件仍会触发快速同步。对没有发出可观察事件的 CSSOM 更新和晚加入的封闭 Shadow DOM，兜底全量检查从每 750 毫秒改为每 1.5 秒；动画期间仍使用较快的绘制节奏。这样减少安静页面反复遍历 DOM 和读取计算样式的开销，代价是少数只改 CSSOM 的静默变化最多延迟约 1.5 秒。
