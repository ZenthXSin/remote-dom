# 诊断日志

进入浏览器工作台，在“更多工具”点击“开始记录数据流”，然后重新加载目标页并重现问题，最后点击“停止并导出日志”。下载文件为 JSON。重复开始会清空本会话上一次记录。刷新工作台后可再次点击停止并导出；日志仅保存在运行中的浏览器会话内，容器或会话结束后不保留。

记录远端请求方法、资源类型、目标源、响应状态、响应等待时间、重定向标记、网络错误代码、主页面和子框架跳转、脚本报错计数事件、页面崩溃、WebSocket 连接状态和采集耗时。Cloudflare 响应会保留合法格式的 Ray ID 和 challenge 标记。导出时附上客户端连接方式、视口和当前显示的操作耗时。

这是诊断元数据，不是完整抓包或 HAR：不记录请求或响应正文、Cookie、Authorization、输入文本、完整 URL 路径、参数和片段。目标域名会保留。脚本错误仅记录发生事件，不保留可能含敏感内容的错误文本。验证路径仅分类为 challenge、widget 或普通资源。代理配置仅记录是否启用，不导出地址或凭据。

每次最多 5 分钟、3,000 条事件。达到条数上限后计数丢弃条目，不继续保存；5 分钟后自动停止。停止后仍可导出，重新开始覆盖旧数据。接口沿用会话归属鉴权和 POST 来源校验，其他账户无法读取。

日志可帮助判断网络失败、验证请求被拒绝、页面反复跳转或显示同步异常；不能直接获得 Cloudflare 的内部判定原因，也不保证通过验证。

版本 2 额外记录路径的短哈希（忽略参数，便于关联同一接口）、API / PAT 请求分类、cf_clearance 与 __cf_bm 是否随请求发送及是否出现在 Set-Cookie 中、开始时当前页面是否存有这两个 Cookie，以及浏览器明确报告的 Cookie 拒收原因。不输出 Cookie 值。记录访问策略拦截事件，区分 DNS 校验失败与其他目标限制。停止或自动到期后关闭额外的 CDP 网络采集。

Cookie 出现在 Set-Cookie 中不等于浏览器已接受，也不意味着服务器认可它；请求携带状态和拒收原因应结合判断。Cloudflare PAT 请求返回 401 也不能单独当作验证失败结论。IPv6-only 探测域名的连接失败需要与同一代理上的普通 IPv6 目标对照，不能仅凭它断定验证循环的唯一原因。

私有代理档案可由运维设置 `ipv4Only: true` 进行 IPv4 对照测试。中继通过原代理查询目标 DNS，校验目标公网地址后，将 HTTPS CONNECT 目标固定为 A 记录地址；TLS 数据仍透传，保留浏览器原来的 SNI 和证书校验。HTTP 请求固定 IPv4 目标并保留原 Host。没有公网 A 记录时拒绝连接，绝不回退直连。新建的对应浏览器和中继容器也禁用内核 IPv6。该选项默认关闭，不代表能消除第三方验证；部分上游代理可能不支持以 IP 为 CONNECT 目标。
