# 客户端资源缓存

图片、字体、音视频等允许展示的二进制资源由用户浏览器的 IndexedDB 保存。客户端先查缓存，未命中才通过经过账户鉴权的资源接口获取；缓存写入失败不影响当次展示。本站自身的 HTML/JS/CSS 仍需由服务端提供。

每个浏览器源最多保存 64 MiB、512 条资源，单条上限 2 MiB，条目有效期 24 小时。容量不足时按最早写入顺序淘汰。过期条目不再命中，在后续写入时清理；这不是定时删除机制，也不是严格 LRU。作用域包含账户派生标识、会话及不透明资源 ID，不能绕过后端账户权限。成功登录、退出登录或修改密码会清空本地资源缓存，同源其他标签页也会收到清理通知。禁用 IndexedDB 时退回普通加载。

服务端保留有界资源来源元数据，不长期保存已交付的二进制正文。缓存未命中时优先读取远端 Chromium 已加载的资源，否则按原代理与目标访问策略流式补取。只重放 GET，重定向逐跳校验，跨域不转发原 Authorization，Cookie 按目标从浏览器上下文获取。请求完成后释放临时正文，相同资源的并发请求合并，最多同时补取四个资源。

Canvas 和部分内联数据需要暂存当前帧才能保证一致性，因此保留总计最多 4 MiB、最长 2 秒、读取后即删除的传输缓冲。客户端会撤销不再引用的 Blob URL，避免动态图像累积占用内存。CSS 字体解析和 SVG DOM 重建仍可能需要服务端读取内容。

远端 Chromium 仍负责执行页面脚本、布局及加载资源，浏览器本身的网络缓存和页面内存仍然存在。本次优化减少 Node 的重复资源存储，不保证单浏览器容器低于 200 MB，也不代表所有资源只经过用户设备。

上游链接过期、资源被替换、浏览器已丢弃内容，或资源只能通过不可重放的请求取得时，缓存未命中仍可能加载失败。代理配置及账户隔离保持原有行为。

验证：47 项单元测试通过；17 项浏览器回归通过。最后边界修正后重新执行了客户端缓存、动态 Canvas、账户注册和退出清理的 3 项浏览器测试，均通过。覆盖刷新命中、容量淘汰、禁用 IndexedDB 降级、跨账户访问限制、代理补取、解压后大小限制和重定向检查。
